# 现货挑战赛需求 Spec

## 1. 文档目的

本 Spec 定义现货挑战赛的业务规则、数据基础、概率模型、仓位与订单管理、风控状态、结算口径和验收标准。当前阶段只确认需求，不进入功能开发。

## 2. 业务目标

通过指定的主流现货白名单、实时行情与历史数据、概率模型、限价分批交易和组合风险管理，提高挑战成功概率并控制尾部损失。系统的目标是形成正期望、可审计、可复盘的自动交易流程，不承诺绝对必胜。

系统必须始终以“账户净清算权益”为挑战判定依据，并以币安真实订单、成交和余额反馈为事实来源。

## 3. 挑战赛规则

### 3.1 本金档位

支持固定本金：

```text
100 / 200 / 500 / 1000 / 5000 / 10000 USDT
```

挑战实例创建后锁定本金和白名单版本。不允许通过外部充值、提币、借贷或保证金改变挑战资金口径。

### 3.2 交易范围

- 只允许 Binance Spot 现货。
- 只允许运营发布的 USDT 现货白名单。
- 不使用杠杆、借贷、保证金、合约或做空。
- 不限制交易次数，但所有订单必须通过组合风险引擎。
- 挑战开始后锁定白名单版本，运营后续更新不影响已开始挑战。

### 3.3 成功与失败

手续费计入挑战阈值，使用净清算权益：

```text
成功：净清算权益 >= 初始本金 × 1.12
失败：净清算权益 <= 初始本金 × 0.97
```

净清算权益应包含可用/冻结 USDT、非 USDT 资产按有效可成交价格估值后的金额，并扣除已确认手续费、预计清仓手续费和可合理估计的滑点。

达到任一阈值后立即停止新增风险，进入清仓流程。挑战不限时，但不允许通过长期挂起规避结算。

### 3.4 手续费

买入和卖出默认按单边 0.04% 作为模型参数，实际成绩以币安成交回报中的真实 commission 为准。系统同时记录毛收益、手续费、滑点和净收益。

## 4. 白名单与基础数据

### 4.1 扫描与筛选

系统定期扫描 Binance Spot `exchangeInfo`，获取交易状态、基础资产、报价资产、精度、步长、最小成交额和订单过滤规则。默认筛选 `quoteAsset=USDT`、`status=TRADING` 的交易对。

自动排除低成交量、盘口深度不足、价差过大、历史数据不足、异常暂停、杠杆代币和不适合小本金的交易对。

### 4.2 运营白名单版本

流程：

```text
交易所扫描 -> 标准化 -> 自动筛选 -> 运营勾选 -> 风控校验 -> 发布版本
```

每个版本记录：交易对、发布人、发布时间、交易规则快照、流动性指标、波动率指标、风险参数和备注。挑战实例必须引用 `spotWhitelistVersionId`。

### 4.3 持续监控

白名单锁定不等于停止监控。持续检查交易状态、成交量、盘口深度、买卖价差、波动率、插针频率、WebSocket 新鲜度和相关性。交易对异常时禁止新增风险；允许撤单、减仓和清仓。

## 5. 数据与事实来源

- WebSocket：实时价格、盘口、成交、订单和账户事件。
- 历史数据：波动率、下行波动率、趋势、回撤、跳针和相关性。
- REST：账户余额、订单、成交、交易规则和对账。

WebSocket 断线、延迟或缓存过期时，禁止新增订单；恢复后必须先通过 REST 对账。订单状态未知时不得重复下单，本地状态不能覆盖币安反馈。

## 6. 概率与组合模型

### 6.1 单币指标

对每个候选交易对计算：

- 触及买入区间概率；
- 限价单成交概率和部分成交概率；
- 达到卖出区间概率；
- 先触及保护线概率；
- 预期持仓时间；
- 净期望值；
- 压力跌幅和跳针风险；
- 对组合的风险贡献。

### 6.2 组合指标

动态展示：

```text
P_success：达到 +12% 的估计概率
P_failure：先达到 -3% 的估计概率
P_stress_failure：压力场景下失败概率
```

模型必须以整个账户路径模拟为主，不能将各币概率简单相加。路径中应包含相关性、手续费、滑点、限价单成交/未成交、部分成交、分批止盈止损和清仓路径。

### 6.3 概率使用原则

概率用于订单审批和风险调整，不是绝对收益承诺。模型结果必须包含样本量、置信区间、样本外验证结果、参数版本和数据时间范围。运营目标可以设置为成功概率显著高于散户基线，但不能把模型概率宣传为必胜保证。

## 7. 动态仓位管理

### 7.1 风险预算

```text
挑战最大亏损 = 初始本金 × 3%
策略计划风险 < 最大亏损
剩余部分用于手续费、滑点、插针和清仓缓冲
```

单币仓位、同类币种仓位和组合仓位均按压力损失、相关性和流动性动态计算，不使用固定满仓规则。

### 7.2 下单前审批

每次新单、补仓、止盈后重新买入前，模拟完全成交、部分成交、未成交后行情变化等情景。只有新增订单不会使组合压力风险超限、失败概率明显恶化，且净期望值符合要求时才允许提交。

未成交限价单也占用预算，必须计入：

```text
已成交仓位 + 未成交挂单预算 + 现金缓冲 + 清仓预留
```

## 8. 订单与执行

### 8.1 限价单

- 限价单最长等待 3 小时。
- 超时自动撤单。
- 撤单、成交和部分成交以币安反馈为准。
- 只对实际成交数量建立止盈止损。
- 未成交订单不能计入实际持仓。
- 撤单后是否重新报价必须重新通过风险审批。

### 8.2 分批止盈

支持多个止盈区间，按实际成交数量管理。止盈后重新买入不是默认行为，必须重新计算组合风险、相关性、费用和失败概率。

### 8.3 分批止损与移动保护

支持分批减仓和移动保护。账户风险接近 -2% 时可以提前启动移动保护，不需要等到 -3%。达到 -3% 后立即停止交易并清仓。

## 9. 风控状态机

```text
READY
  -> NORMAL
  -> CAUTION
  -> PROTECT
  -> REDUCE_ONLY
  -> SUCCESS_PENDING_CLEAR / FAILURE_PENDING_CLEAR
  -> CLEARING
  -> SUCCEEDED / FAILED
```

- `NORMAL`：按计划执行。
- `CAUTION`：波动率或风险升高，降低新增仓位。
- `PROTECT`：接近风险线，优先止盈、减仓和移动保护。
- `REDUCE_ONLY`：极端行情，不暂停挑战，但禁止新增风险，只允许撤单、减仓和清仓。
- `CLEARING`：撤单并清算全部非 USDT 资产。

极端行情不能通过“暂停挑战”逃避结算；系统必须切换为减仓或清仓模式。

## 10. 清仓与成绩

达到阈值后：

1. 原子锁定挑战，停止新订单；
2. 撤销全部未成交订单；
3. 卖出全部非 USDT 资产；
4. 等待成交回报；
5. REST 对账余额和成交；
6. 记录触发快照与清仓后最终成绩；
7. 状态变更为 `SUCCEEDED` 或 `FAILED`。

记录内容包括触发时间、触发净权益、清仓净权益、手续费、滑点、订单 ID、成交明细、白名单版本、模型版本和异常事件。

## 11. 验收标准

- 挑战只能交易锁定白名单中的现货交易对。
- 买卖手续费会影响成功/失败判定。
- 未成交挂单会占用预算并参与风险计算。
- 限价单超过 3 小时自动撤单，部分成交数量准确管理。
- 每次新单前重新计算单币和组合风险。
- WebSocket 异常时禁止新增单，REST 可完成对账。
- 订单未知状态不会重复下单。
- 达到 -2% 可以提前移动保护，达到 -3% 必须结束挑战。
- 极端行情进入 `REDUCE_ONLY`，不暂停挑战。
- 清仓后以币安真实余额和成交结果完成结算。
- 能输出单币概率表、组合概率表、压力损失、置信区间和模型版本。
- 历史回测、样本外测试、压力测试和小资金实盘验证均通过后，才允许扩大资金规模。

## 12. v1 已确认参数配置

以下参数已确认，作为第一版实现和测试基线。参数应配置化，不应散落在策略代码中。

### 12.1 白名单与数据质量

| 参数 | v1 值 |
|---|---:|
| 报价资产 | `USDT` |
| 交易状态 | `TRADING` |
| 最低历史数据 | 30 个自然日 |
| 24 小时最低成交额 | 500 万 USDT |
| 最大买卖价差 | 15 bps |
| ±0.5% 盘口深度 | 计划单金额的至少 20 倍 |
| 最新行情最大延迟 | 3 秒 |
| 24 小时异常插针观察阈值 | 超过 3 次进入观察 |
| 限价单有效期 | 3 小时 |

### 12.2 波动率状态

| 状态 | 24 小时波动率 | 动作 |
|---|---:|---|
| `NORMAL` | ≤ 5% | 正常执行 |
| `CAUTION` | 5%～8% | 新仓位金额减半 |
| `PROTECT` | 8%～12% | 禁止新增，只允许减仓和止盈 |
| `REDUCE_ONLY` | > 12%或发生严重数据/盘口异常 | 撤单、减仓、清仓 |

### 12.3 组合风险和仓位

| 参数 | v1 值 |
|---|---:|
| 挑战硬失败线 | 3.0% |
| 策略正常风险预算 | 1.8% |
| 滑点、手续费、插针缓冲 | 0.6% |
| 紧急清仓缓冲 | 0.6% |
| 初始最大资金使用率 | 60%～65% |
| 现金和预留资金 | 35%～40% |
| 单币正常最大仓位 | 15% 本金 |
| 单币高波动最大仓位 | 8%～10% 本金 |
| 单币压力风险 | 0.6% 本金 |
| 单次新增订单压力风险 | 0.3% 本金 |
| 高相关币种合计仓位 | 35% 本金 |
| 单币连续补仓 | 最多 2 次 |
| 亏损加倍补仓 | 禁止 |

### 12.4 自动下单与保护线

下单不需要人工审批。策略产生订单后，由组合风险引擎同步计算；通过即直接提交币安订单，不通过则拒绝或延后。

| 账户净收益 | 自动动作 |
|---:|---|
| `-1.0%` | 新增订单金额减半 |
| `-1.5%` | 禁止普通加仓，只允许降低风险 |
| `-2.0%` | 启动移动止损和保护性减仓 |
| `-2.5%` | 强制减仓/清仓准备 |
| `-3.0%` | 挑战失败，立即清仓 |
| `+10.0%` | 提高止盈保护 |
| `+11.5%` | 停止扩大风险，保护已实现收益 |
| `+12.0%` | 挑战成功，停止新增并清仓 |

### 12.5 概率审批门槛

| 指标 | v1 要求 |
|---|---:|
| 基础场景失败概率 | ≤ 15% |
| 压力场景失败概率 | ≤ 30% |
| 新单导致失败概率增幅 | ≤ 3 个百分点 |
| 新单净期望值 | > 0 |
| 95% 损失分位 | 不超过剩余风险缓冲 |
| 数据有效性 | WebSocket 延迟 ≤ 3 秒 |

这些门槛是自动风险引擎的执行条件，不是人工审批条件；所有阈值都必须通过历史回测、样本外测试、压力测试和小资金实盘校准。

### 12.6 订单事实来源

订单创建、成交、部分成交、撤单和清仓均以币安反馈为准。网络超时或 WebSocket 与 REST 不一致时，先查询和对账，禁止根据本地猜测重复下单。

## 13. 下一阶段边界

下一阶段可以开始数据库结构、概率计算服务、组合风险引擎、现货订单适配器、白名单运营页面和测试用例设计；不改变本 Spec 已确认的业务规则和 v1 参数。
